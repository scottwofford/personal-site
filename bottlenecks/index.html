Bottlenecks

Where AI safety tooling gets stuck, through a Theory of Constraints lens.

TL;DR

  • Control Tower (open-source software for AI control researchers): constraints are human PR review and high-quality user feedback; poor docs are a reverse flywheel. Goal: accelerate high-quality control and security research.
  • Talent: constrained by well-scoped roles for security engineers, plus senior maintainers (Senior Principal and Principal engineers) to keep software working.
  • Luthien: same lens with frontier AI auditors as users; goal: accelerate the steps in Luthien's theory of change.

What would loosen it

  • Review capacity: more people who can review PRs that end up merged. Faster bots don't help; human review is the wait.
  • User feedback: docs good enough that a new researcher finishes a first eval run alone, then reports what broke.
  • The loop: improving any one link (better docs, or protected review time) turns the vicious cycle into a virtuous one.
