Where security talent gets stuck

There are capable security engineers who want to work on AI agent tooling. Two valves decide how many of them end up producing working software.

Scroll the diagram sideways →

stock (people waiting or working) flow ⚠ valve that limits the flow || delay   cloud = outside the system

How to read it

  • Inflow is not the problem. Capable people show up. Without a scoped role they sit in the first stock, and over time they drift to other work.
  • Valve 1, scoped roles: well-defined work a security engineer can pick up, such as finding and fixing security bugs in open-source agent tooling.
  • Valve 2, senior maintainers: contributors' work only becomes working software when a Senior Principal or Principal engineer reviews and keeps the software running. Adding contributors without adding this capacity makes the review queue longer.
